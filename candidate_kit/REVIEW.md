# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| #   | Where (function / line)                                  | What is wrong                                                                                                                                                                                                                                                                                     | How you'd notice it (test, input, or symptom)                                                                                      | How you fixed it                                                                                                                                          |
| --- | -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | `compute_late_minutes` / `compute_overtime` / `punch_in` | The helper logic ignores IST-aware shift boundaries and overnight-shift rules; it also fails to normalize input times and uses naive datetime comparisons. The punch-in endpoint sets the day's record with a plain local date, which breaks overnight shifts and timezone-correct date handling. | Any employee with `shift_start`/`shift_end` such as `22:00`-`06:00` or any punch-in after midnight fails the attendance-date rule. | Replaced the logic with IST-aware attendance-date resolution, overnight shift handling, and exact R1-R5 calculations.                                     |
| 2   | `compute_work_hours`                                     | It rounds using Python's default float behavior and does not follow the required half-up rounding rule.                                                                                                                                                                                           | A value such as `9.125` can come out as `9.12` or `9.13` depending on binary floating-point behavior.                              | Implemented `Decimal` half-up rounding for all derived calculations and analytics percentages.                                                            |
| 3   | `punch_in` endpoint                                      | The endpoint does not enforce presence-only statuses, does not validate `punched_at`, does not convert times to milliseconds/UTC properly, and computes the record date from the raw system clock rather than the IST shift semantics.                                                            | Punching in with `status=ABSENT`, `status=LEAVE`, or a `punched_at` outside the required validation range is accepted incorrectly. | Added explicit validation for `PRESENT`/`WFH`/`ON_DUTY`, validated epoch milliseconds, and resolved the attendance date using the employee's shift rules. |
| 4   | `list_employees`                                         | Pagination uses `skip = page * page_size` instead of `(page - 1) * page_size`, so page 1 skips the first page entirely; `total` also ignores the applied filter.                                                                                                                                  | A request to page 1 returns the second page of results.                                                                            | Fixed pagination and filter-aware counting to match the contract.                                                                                         |
| 5   | `punch_out` endpoint                                     | The starter has no implementation for it. It also never enforces `punch_out` being after `punch_in`, within 24 hours, or matching the employee's shift end rules.                                                                                                                                 | Any punch-out request produces a missing endpoint or invalid results.                                                              | Implemented the endpoint with strict validation, concurrency-safe update semantics, and R3-R5 derived fields.                                             |
| 6   | `list_attendance`                                        | It sorts by raw date string but does not validate `date_from <= date_to`, ignores the required `page`/`page_size` semantics, and returns a developer-only `_id` field instead of the contract's natural shape.                                                                                    | `date_from` greater than `date_to` is silently accepted, and the response does not match the OpenAPI schema.                       | Added validation and normalized the response to the contract, including date-range validation and proper pagination.                                      |
| 7   | `regularize` endpoint                                    | It is completely absent, despite being a required contract. There is no audit trail, no recomputation of values, no change-detection, and no handling of invalid combinations such as ABSENT + punch times or no-op patches.                                                                      | The endpoint returns 404, or it does not exist.                                                                                    | Implemented the full manual correction flow with a `history` append, recomputation rules, and validation.                                                 |
| 8   | Analytics endpoints                                      | All analytics routes are missing; the file explicitly leaves the whole analytics/API section unimplemented.                                                                                                                                                                                       | The app does not satisfy the grading contract or any analytics checks.                                                             | Implemented all required aggregation endpoints: monthly summary, department summary, leaderboard, trend, and explain.                                     |
| 9   | Startup/indexing                                         | There are no required MongoDB indexes or unique constraints for employee codes and attendance records. Concurrent duplicate requests can silently create bad data.                                                                                                                                | Duplicate employee codes or duplicate punch-ins for the same date slip through.                                                    | Added startup index creation with unique indexes and concurrency-safe duplicate handling.                                                                 |
| 10  | Health endpoint                                          | It always returns 200 without checking whether MongoDB is reachable.                                                                                                                                                                                                                              | The grader polls `/health` and expects 503 when the DB is offline.                                                                 | Added a live MongoDB ping and proper 503 behavior.                                                                                                        |

Also note anything I looked at and decided was not a defect, and why.

- The use of a single `app/main.py` file is intentional and matches the assignment: all implementation is confined to one file as specified by the repository instructions.
- The starter's `datetime.now()` usage is acceptable for server-set timestamps, but it must be converted to UTC and epoch milliseconds at the boundary, which is exactly how the final implementation handles it.
- The employee `created_at` field is server-generated and should not be client-supplied; the starter's pattern already matches that intention, but it was tightened with validation and consistent serialization.
